# حُجَّة

**حُجَّة — الذكاء الاصطناعي للتحقق العلمي والبحث في المراجع الإسلامية الصحيحة**

> يبحث حُجَّة في المراجع الإسلامية عبر **تراث**، ثم يعرض الإجابة مع أدلتها ومصادرها الأصلية للتحقق منها.

بالإنجليزية عند الحاجة: **Hujjah**. النطاق الرسمي: <https://hujjah.maaoun.com>

**تراث هي مصدر البحث الوحيد** في حُجَّة: يبحث في محتوى مكتبة تراث (app.turath.io) عبر واجهتها العامة، ثم يصوغ إجابة عربية مستندة حصرًا إلى المقاطع المسترجَعة، ويعرض الاستشهادات داخل نص الإجابة نفسها — قابلة للضغط — مع الأدلة وروابط المواضع الأصلية.

> حُجَّة ليس منصّة لإعطاء «رأي ذكاء اصطناعي»، ولا يُصدر فتوى.
> دوره: **يبحث ← يستخرج ← يقارن ← يلخّص ← يوثّق.**

---

## 1. نتيجة الفحص التقني للمصدر

قبل كتابة أي كود، فُحص المصدر للتحقق من طريقة وصول **حقيقية ومستقرة ومسموحة**. هذه النتيجة:

### تراث — ✅ متاح ومُتحقَّق منه عمليًا

واجهة JSON عامة على `api.turath.io`، بلا مفتاح وبلا حساب. نقاط النهاية المستخدمة:

| النقطة | الاستخدام |
|---|---|
| `GET /search?q=&ver=3` | بحث نصي في المتون |
| `GET /page?book_id=&pg=&ver=3` | نص صفحة بعينها |
| `GET /book?id=&ver=3` | بيانات الكتاب وتصنيفه |
| `GET /author?id=&ver=3` | ترجمة المؤلف |

استجابة البحث تُرجع لكل نتيجة: `book_name`، `author_name`، `vol`، `page`، `page_id`، `headings[]`، `snip`، `text`.
رابط الموضع الأصلي يُبنى كـ `https://app.turath.io/book/{book_id}/{page_id}`.

**مهم:** لا يستخدم حُجَّة إجابة الذكاء الاصطناعي الجاهزة من تراث. يأخذ منها **نتائج البحث والنصوص فقط**، ونظامنا هو الذي يجمع الأدلة ويقرّر ما يُمرَّر للنموذج.

**ملاحظة تاريخية:** كان المشروع سابقًا يبحث أيضًا في المكتبة الشاملة، ثم حُذف ذلك المسار بالكامل (محوّل الشاملة، عميل MCP، متغيراته، وحالاته) بعد التحقق من أن محتوى الشاملة متوفر ضمن تراث. مصدر البحث والاستشهادات اليوم هو **تراث فقط**، ولا يتصل التطبيق بـ `shamela.ws` بأي طريقة، وروابطها مرفوضة ضمن قائمة النطاقات المسموحة.

للتحقق من حالة الخدمة فعليًا بعد النشر:

```bash
curl -s 'https://<نطاقك>/api/health?probe=1' | jq
```

## 2. التشغيل

```bash
npm install
cp .env.example .env.local      # ثم ضع مفتاح Gemini في .env.local
npm run dev                     # http://localhost:3000
```

| المتغيّر | مطلوب | الوصف |
|---|---|---|
| `GEMINI_API_KEY` | ✅ | من <https://aistudio.google.com/apikey> |
| `GEMINI_MODEL` | — | الافتراضي `gemini-2.0-flash` |
| `GEMINI_THINKING_BUDGET` | — | ميزانية «التفكير». الافتراضي `0` على نماذج flash (يمنع الاستجابات الفارغة) |
| `GEMINI_BASE_URL` | — | الافتراضي `https://generativelanguage.googleapis.com/v1beta` |
| `TURATH_API_BASE` | — | الافتراضي `https://api.turath.io` |
| `TURATH_APP_BASE` | — | الافتراضي `https://app.turath.io` |
| `TURATH_ENABLED` | — | `false` لتعطيل مصدر البحث |
| `RATE_LIMIT_PER_MINUTE` | — | الافتراضي `10` |
| `MAX_QUESTION_CHARS` | — | الافتراضي `500` |
| `HUJJAH_DEV_FIXTURES` | — | وضع التطوير فقط (لا يعمل في الإنتاج) |

أسماء بديلة مقبولة للمفتاح نفسه (للتوافق مع منصات النشر): `GOOGLE_API_KEY`، `GOOGLE_GENERATIVE_AI_API_KEY`، `GOOGLE_AI_API_KEY`، وأخيرًا `GEMINI_API_KEY_BUILD` (احتياطي يُحقن من بيئة البناء في CI فقط).

**المفتاح يُقرأ على الخادم فقط.** لا يصل إلى المتصفح، ولا يظهر في أي سجل، وتُنقّى رسائل أخطاء Gemini منه قبل عرضها. ويُقرأ **لحظة الطلب** من `process.env` ثم من سياق Cloudflare — لا عند تحميل الوحدات — لأن أسرار Workers لا تكون جاهزة وقت التحميل.

للتحقق السريع من المفتاح:

```bash
npm run check:gemini                                 # يفحص المفتاح محليًا لدى Google
npm run check:gemini -- https://hujjah.maaoun.com    # يفحص النسخة المنشورة
```

### النشر على Cloudflare والنطاق

هذا المشروع مُعَدّ لـ **Cloudflare Workers عبر OpenNext**، لا لـ Cloudflare Pages/static export؛ لأن المسارين `/api/ask` و`/api/health` يحتاجان تنفيذًا خادميًا ومفتاح Gemini سريًا.

```bash
npm run preview  # يبني التطبيق ويشغّله محليًا على runtime Workers
npm run deploy   # يبني وينشر Worker باسم qaf
```

`npm run build` ينفّذ ثلاث خطوات: `next build` ← تحويل OpenNext إلى `.open-next` ← فحص مفتاح Gemini (`scripts/prepare-preview.mjs`) الذي يطبع في سجل البناء هل المفتاح متاح ومن أين. محليًا لا يعدّل هذا السكربت أي ملف؛ وداخل CI فقط — وإن وُجد المفتاح في بيئة البناء — يحقنه في `wrangler.jsonc` باسم احتياطي `GEMINI_API_KEY_BUILD` حتى لا يصطدم بالسرّ الحقيقي ولا يحوّله إلى نص ظاهر.

### ⚠️ مفتاح Gemini على Cloudflare: الإعداد الصحيح

1. **اضبطه كـ Secret لوقت التشغيل**: Cloudflare → Workers & Pages → `qaf` → **Settings → Variables and Secrets** → Add → **Type: Secret** → Name: `GEMINI_API_KEY` → Deploy.
   أو من الطرفية: `npx wrangler secret put GEMINI_API_KEY`
2. **«Build variables and secrets» ليست كافية.** متغيّرات البناء تصل إلى `next build` فقط ولا يراها الـ Worker أثناء التشغيل. هذا أشهر سبب لرسالة «مفتاح Gemini غير مضبوط» رغم أن المفتاح يبدو مضبوطًا في اللوحة.
3. **لا تحذف متغيّرات اللوحة عند النشر**: `wrangler deploy` يمسح المتغيّرات النصية غير المذكورة في ملف الإعداد. لذلك أُضيف `"keep_vars": true` في `wrangler.jsonc`، وأمر النشر صار `opennextjs-cloudflare deploy -- --keep-vars`.
4. **تأكّد من الـ Worker الصحيح**: الاسم هنا `qaf`. ضبط السرّ على Worker آخر أو على مشروع Pages لا يفيد.
5. **بعد النشر تحقّق فعليًا**:

```bash
curl -s 'https://hujjah.maaoun.com/api/health?probe=1' | jq '.ai, .probe.gemini'
```

يبيّن الناتج: هل وُجد المفتاح (`ai.key.found`)، ومن أي متغيّر (`ai.key.variable`)، ومن أي مصدر (`process.env` أو `cloudflare`)، وهل قبِله Google فعلًا (`probe.gemini.ok`). ولا تُكشف قيمة المفتاح في أي حال.

| ما تراه | المعنى | الإصلاح |
|---|---|---|
| `key.found = false` | الـ Worker لا يرى المفتاح | أضفه كـ Secret لوقت التشغيل ثم أعد النشر |
| `probe.gemini.code = "auth"` | Google رفض المفتاح | مفتاح خاطئ/مقيَّد، أو الواجهة غير مفعّلة لمشروعه |
| `probe.gemini.code = "model_not_found"` | المفتاح سليم والنموذج غير متاح | غيّر `GEMINI_MODEL` |
| `probe.gemini.code = "rate_limit"` | تجاوز الحصّة | انتظر أو ارفع الحصّة |

لا تضع المفتاح داخل `wrangler.jsonc` في Git. لا حاجة إلى قاعدة بيانات أو Supabase في النسخة الحالية.

**النطاق المقصود لهذا المشروع هو النطاق الفرعي فقط:**

```
hujjah.maaoun.com
```

- من Cloudflare Workers → `qaf` → Settings → Domains & Routes، أضف `hujjah.maaoun.com` كـ **Custom Domain**. ينشئ Cloudflare سجل DNS والشهادة تلقائيًا عندما تكون zone `maaoun.com` في الحساب نفسه.
- لا تضف `maaoun.com` أو `www.maaoun.com` كـ Custom Domain أو Worker Route لهذا الـ Worker، ولا تنشئ إعادة توجيه منهما إلى حُجَّة.
- اسم الـ Worker الداخلي هو `qaf`، وقيمة `WORKER_SELF_REFERENCE` في `wrangler.jsonc` هي `qaf` كذلك؛ لا تغيّر أحدهما دون الآخر.
- `metadataBase` و Open Graph و`canonical` مضبوطة على `https://hujjah.maaoun.com`، كما أن عنوان ووصف SEO والكلمات المفتاحية مضبوطة في `src/app/layout.tsx`.
- اترك إدارة `maaoun.com` ومحتواه في إعداد Cloudflare الأصلي، منفصلًا عن خدمة حُجَّة.

### مسار الطلب

```
سؤال المستخدم
  ↓ التحقق + تحديد المعدّل + رفض محاولات تغيير القواعد
  ↓ [Gemini] تحليل السؤال → 1–3 استعلامات بحث عربية
  ↓ البحث في تراث (JSON API) — المصدر الوحيد
  ↓ استخراج النتائج والأدلة (كتاب، مؤلف، جزء، صفحة، نص، رابط)
  ↓ تنظيف + إزالة تكرار + ترتيب + ترجيح المذهب
  ↓ [Gemini] صياغة مستندة إلى المقاطع فقط (JSON مهيكل)
  ↓ التحقق: حذف كل استشهاد بمعرّف غير موجود
إجابة + استشهادات داخلية قابلة للضغط تفتح المصدر في تراث
```

كل مرحلة تُبثّ إلى الواجهة فور وقوعها، فيرى المستخدم حالة المصدر لحظيًا.

### الاستشهادات داخل الإجابة

المصادر لا تُعرض في قسم منفصل أسفل الإجابة، بل كاستشهادات صغيرة قابلة للضغط بجانب الجملة التي تسندها تحديدًا، مثل: «… سنة عند الشافعية `[المجموع 3/301]`». وعند الضغط تظهر نافذة ببيانات المصدر الكاملة من تراث:

- اسم الكتاب والمؤلف كاملين.
- الجزء والصفحة إن وردا في بيانات المصدر.
- النص المستخرج (مع إمكانية عرضه كاملًا).
- زر يفتح الموضع الأصلي في موقع تراث (`app.turath.io/book/{id}/{page_id}`).

كل إحالة مرتبطة بمعرّف دليل حقيقي من نتائج البحث؛ ولا يمكن للنموذج اختراع استشهاد لأن أي معرّف غير موجود يُحذف برمجيًا قبل العرض.

## 4. ضمانات عدم التلفيق

| الخطر | الإجراء |
|---|---|
| نسبة كلام إلى كتاب لم يُسترجع | النموذج لا يرى إلا المقاطع المسترجَعة؛ وكل استشهاد بمعرّف غير موجود يُحذف برمجيًا بعد التوليد |
| اختراع رقم صفحة أو جزء | الأرقام تُمرَّر من حقول المصدر فقط؛ وعند غيابها يُكتب صراحةً «غير متوفرة» ولا يُطلب من النموذج تقديرها |
| إجابة من المعرفة العامة | عند انعدام الأدلة أو انعدام الاستشهادات الصالحة تُجبر النتيجة على `insufficient` ولا يُعرض نص إجابة |
| فشل مصدر البحث | لا إجابة تخمينية: «تعذّر الوصول إلى مكتبة تراث حاليًا، لذلك لم أتمكن من التحقق من الإجابة.» |
| روابط ملفّقة | كل رابط يمرّ على قائمة نطاقات بيضاء (`turath.io` فقط) وإلا تُستبعد النتيجة كليًا |
| تصنيف مذهبي من عندنا | انظر القسم التالي |

### فلتر المذهب

الفلتر **ترجيحي لا إقصائي**: يرفع ترتيب المطابق ولا يحذف غيره.

ولا نصنّف أي كتاب أو مؤلف من عندنا. سند التصنيف أحد اثنين فقط، ويُعرض للمستخدم في تفاصيل الاستشهاد:

1. **تصنيف الكتاب في تراث** — مطابقة دقيقة لمجلدات التصنيف الرسمية (`الفقه الحنفي` / `المالكي` / `الشافعي` / `الحنبلي`).
2. **ترجمة المؤلف في تراث** — ورود وصف المذهب حرفيًا في الترجمة المنشورة في تراث.

ما لم يتوفّر أحدهما يبقى المذهب **غير معروف**، فلا شارة ولا ترجيح ولا ادّعاء.

## 5. الأمان

- المفتاح في متغيّرات البيئة، على الخادم فقط، ومُنقّى من رسائل الأخطاء.
- تحديد معدّل لكل IP (افتراضي 10/دقيقة) على `/api/ask` و`/api/health`.
- حدود صارمة: طول السؤال، حجم الطلب، عدد الاستعلامات، عدد المقاطع، طول المقطع، مهلة المصدر.
- **لا تنفيذ لأي HTML أو JavaScript** قادم من المصدر: كل نص يمرّ على `toPlainText` (إزالة وسوم → فكّ كيانات → إزالة وسوم مجددًا → إزالة محارف التحكم والاتجاه)، والعرض بنص عادي بلا `dangerouslySetInnerHTML`.
- روابط النتائج تحمل `rel="noopener noreferrer nofollow"` ولا تُقبل إلا من نطاق `turath.io`.
- رفض الطلبات التي تحاول تغيير قواعد النظام قبل وصولها إلى النموذج، وتحييد أنماط الأوامر داخل نصوص المصدر.
- ترويسات أمان على كل المسارات (`X-Content-Type-Options`، `Referrer-Policy`، `X-Frame-Options`، `Permissions-Policy`).

## 7. وضع التطوير (معزول)

للعمل على الواجهة بلا اتصال بالمصدر:

```bash
HUJJAH_DEV_FIXTURES=true npm run dev
```

- يعمل فقط عندما يكون `NODE_ENV !== 'production'` **و** المتغيّر مضبوطًا — مستحيل تفعيله في الإنتاج.
- يعرض شريطًا أصفر دائمًا في أعلى الصفحة يوضّح أن النتائج من ملف محفوظ.
- البيانات المحفوظة **ليست مخترعة**: نسخة حرفية من استجابة حقيقية لواجهة تراث (بحث فقط)، بلا تعديل في اسم كتاب أو مؤلف أو جزء أو صفحة أو نص.
- لا يؤثّر على النموذج: الإجابة تتطلّب مفتاح Gemini حقيقيًا في كل الأحوال.

## 8. نطاق النسخة الحالية

- بحث مباشر في **تراث فقط** — بلا فهرسة محلية وبلا تحميل كتب إلى قاعدة بيانات، وبلا أي مصدر بحث آخر.
- بلا حسابات، بلا قاعدة بيانات.
- عند اختلاف المقاطع يُعرض الخلاف صراحةً ويُنسب كل قول إلى مقطعه، دون ترجيح.
